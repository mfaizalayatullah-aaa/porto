Consumer · Growth

Homepage: let the data set the block order

Role
Analysis, design, experiment plan
Partners
Growth, Design, Data

Insight

I joined impressions with sales by touchpoint. The most-seen block was not the one that sold, and one of the strongest sales sources sat below the fold.

What I did

  • Proposed a new block order and a one-line account strip (points · vouchers · check-in)
  • Compared four first-screen layouts side by side
  • Recommended a 3-arm A/B test instead of a big-bang redesign
Lesson: a layout that "looks busy" is not the problem to fix. The useful question is which block earns its space.

Experience

From solving the problem to defining it

In TechOps my job was the solution: find the root cause, fix it, keep the system up. As a PM my job starts before that: decide which problem is worth solving, for whom, and how we will know it is solved.

TechOps · solution-first
  • "What is broken, and how fast can we fix it?"
  • Success = incident closed within SLA
  • Starts from the alert or the ticket
→
PM · problem-first
  • "Who is affected, how much, and is it worth solving now?"
  • Success = a measurable outcome, agreed before building
  • Starts from a problem statement backed by data
